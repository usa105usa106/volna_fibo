# v0026 — ограниченные уточнения к протоколу v0025

Протокол `majors-0025-20261005`, его senior-якоря, ETH-сценарий, hard invalidation и Fib-формулы сохраняются. Новых исключений для тикеров или готовых цен V2 нет. Общий детектор других активов не меняется.

## Поиск независимой пятёрки BTC V2

V2 проверяет участок parent W2 → общий high независимо от V3. Используются прежние центрированные swing-pivots, сначала COMPLETE4H, затем 1H как поддержка. Внутренние вершины берутся только из свечей выбранного рынка. Для H1 точное время крайней цены ищется внутри соответствующего COMPLETE4H-бакета: senior-якорь при этом не переносится на H1.

Поиск строит допустимые направленные связи между реальными разворотами. Вся свечная область каждого участка должна укладываться между его крайними ценами: скрытые overlap/origin-wicks нельзя отбросить вместе с промежуточными колебаниями. Затем проверяются строго возрастающее время, растущие вершины, W2 origin, W4 overlap, запрет кратчайшей W3, глубины коррекций 0.08–0.95, минимум 12 часов на каждую волну и отношение длительностей не более 20. Минимальная значимость движения сохранена: max(6% длины проверяемого импульса, 1.5 median ATR).

Промежуточные меньшие развороты могут оставаться внутри одной ноги старшей пятёрки. Поэтому наличие более шести исходных pivots само по себе не отклоняет V2. Из нескольких допустимых пятёрок выбирается самая крупная по минимальной амплитуде ноги, затем по согласованности длительностей. Цены целей, имя BTC и желаемый PRIMARY в этот выбор не входят.

Состав и веса оценок сохранены. На архивных Binance-свечах найдена пятёрка 62275 → 65474.46 → 62535.24 → 82300 → 74967.97 → 87395.67: V2=8.5, V3=9.0 без бонуса ETH/BTC. Это результат расчёта по parquet, а не заданные runtime-уровни. После моделируемого выхода из BOX разница 0.5 означает UNRESOLVED, рабочий PRIMARY V3 и живую ALT V2. Когда по данным V2 действительно лучше, она может стать PRIMARY.

Нет найденной пятёрки: `UNPROVEN`, `hard_rules=UNKNOWN`, `total=null`; не `0/10`, не доказанное PASS и не RETIRED. Полное численное сравнение при таком результате невозможно, поэтому остаётся UNRESOLVED и условная ALT. Доказанное hard invalidation по-прежнему отменяет count немедленно независимо от рейтинга.

Мягкая смена уже выбранного PRIMARY требует преимущества >=2 на двух разных последовательных COMPLETE4H. Повторный опрос одного бакета не увеличивает серию; пропуск бакета её сбрасывает. Обновление с v0025 очищает только прежнюю soft-серию/оценку, включая повторный расчёт в том же бакете. PRIMARY и реестр RETIRED не стираются; старый count не восстанавливается.

## Зоны BTC V1

L — рабочий W3-(4) low, H — предшествующий W3-(3) high, B — нижняя граница BOX выбранной биржи.

- База: `[L, L + 0.236 × (H − L)]`.
- На вынос: `[max(B, L − 0.05 × (H − L)), L]`, с прежним буфером `B × 1.0005`, когда он лежит строго ниже L.
- Если L = B, база остаётся доступной, но законной зоны ниже low уже нет: «На вынос» пусто. Зону нельзя перевернуть или перенести над low.

Это контекст исполнения V1, не изменение границ его валидности. V1 сохраняет только структурный верхний предел W3-(5), без вымышленных extension targets. После отмены V1 зоны принадлежат выбранной V2/V3; при полном invalidation зоны не показываются.

На числах присланного MEXC manual: L=82502.4, H=87378.8, B=82256.9. База 82502.4–83653.2304; на вынос 82298.02845–82502.4. Этот пример проверяет арифметику по отчёту, не новую загрузку MEXC OHLC.
