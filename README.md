# Telegram Senior Wave Scanner v0022

Версия 0022 добавляет общий контроль зрелого импульса после старшей W2. Перед выдачей новых целей бот проверяет, не видна ли уже последовательность пяти старших движений внутри предполагаемой W3-(1). При таком конфликте степени выводится **W4? · кандидат**, статус `PHASE_UNCERTAIN`, без рейтинга входа, лимитных зон и целей W2/W3-(2). Это кандидат разметки, не доказательство единственной Elliott-интерпретации. Исключений ZEC/BCH и констант их цен в алгоритме нет.

Наблюдаемая старшая стадия сохраняется в Track, даже если начало импульса вышло из скользящего окна. Пробой области W1 отправляет эту гипотезу на пересчёт. Пять движений могут оказаться расширением внутри W3: бот явно показывает эту неопределённость и не выдаёт старую формулу за цели W5. Формула Fib и коэффициенты рейтинга существующих W2/W3-(2) не менялись.

Проверено по архиву **03.10.2026 20:54:34 MSK**, дополненному официальной H1-историей Binance: ZEC — кандидат W4 после 368.03 → 589.18 → 451.75 → 888 → 751.53 → 1698, рабочий low 1271.09. Это не проверка текущих live-котировок. Исходные ошибки, результаты тестов и ограничения: `AUDIT_v0022.md`, изменения: `CHANGELOG_v0022.md`.

Сохранённые исправления версии 0021: она исправляет выбор начала целевого импульса при потере старшего родителя за границей часовой истории и добавляет проверяемую историю TON → GRAM. База изменений — 0020, происходящая из приложенной 0018. Это исходники бота, а не только offline-отчёт. Развёртывание на вашем сервере автоматически не выполнялось.

## Что исправлено

- Старший подтверждённый D1 parent имеет приоритет над внутренними коррекциями. Для BCH цепочка 181 → 255.1 → 199.7 сохраняет origin 199.7 в текущем импульсе к 366.4. Внутренние lows 212.8/239 не понижают степень. Fib, strict origin, цели и рейтинг пересчитываются вместе.
- Если D1 показывает более старший parent, а его W2 нет в доступных COMPLETE4H, выводится DATA_INCOMPLETE без спорных целей. Search не считает такую историю успешной; Track сохраняет прежнее состояние в БД.
- Предшествующий TON подгружается только с той же биржи: официальные месячные архивы Binance с SHA256 либо API MEXC для TON_USDT. Дневной контекст не превращается в выдуманные 4H свечи.
- При недоступной истории TON таблица показывает «степень? · нет истории TON». Доступные три опоры и условные цели остаются в диагностике; W3-(2) не назначается по одному названию тикера.
- Первый Track после обновления пересчитывает сохранённые тикеры. Терминальные INVALID/RECOUNT не оживают. Когда ранее недоступная история TON появляется, тот же тикер пересчитывается повторно.

Формула целей сохранена: `working_low + m × (high − origin)`, где `m = 1 / 1.618 / 2.618 / 4.236`. Коэффициенты рейтинга не менялись. Ограничения — `METHODOLOGY.md`; исходные строки ошибок и проверки — `AUDIT_v0021.md`.

## Обновление

1. Сохраните volume `/data` и резервную копию SQLite.
2. Разверните этот архив целиком. Если в Coolify задан `BOT_VERSION`, установите `0022` или удалите переопределение. Пересоберите образ и убедитесь, что таблица подписана v0022.
3. Первый Track обновит только сохранённые тикеры; Reset для миграции не нужен. Если новые опоры не подтверждаются, старые цели убираются и выставляется RECOUNT.
4. Новый Search заменяет tracked-set после доставки отчёта и атомарного commit. При ошибке доставки прежний набор сохраняется.

```bash
cp .env.example .env
# Заполните BOT_TOKEN; не включайте .env в публичный репозиторий.
docker compose up --build -d
```

Coolify: Dockerfile, один процесс long polling, постоянный volume `/data`. Несколько реплик с одним Telegram token не поддерживаются. Runtime-файлы лежат в корне; `fixtures/` и `audit/` нужны для проверок. Бот не размещает ордера. Для SOCKS-прокси HTTPX требуется дополнительно `socksio`; стандартному запуску без него этот пакет не нужен.

Search работает с Top-100/200/300. Track обновляет последний успешно сохранённый набор. Отсутствующие XAU/USOIL не заменяются другими инструментами. Ручной ввод `doge,pol,sol` и `/walk` не меняют рабочий tracked-set. Автоинтервал отсчитывается от успешной доставки полного отчёта.

## Тесты и воспроизведение

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check . --select E9,F
python -m compileall -q .
python -m bandit -r . -x './test*,./conftest.py'
python replay_archive.py fixtures/market_2057 --symbols ZEC,BCH,LTC,DOGE,GRAM,XAU,USOIL --predecessor-daily fixtures/ticker_history/binance_TON_1d.parquet --hourly-prefix fixtures/hourly_history/binance_BCH_ZEC_1h_prefix.parquet --output replay
```

Offline replay не использует сеть, SQLite или Telegram. Проверка сокращённой истории LTC выводит нехватку старых H1, а не прошитые меньшие цели. Live бот уже запрашивает 120 дней H1 по умолчанию; не сокращайте LOOKBACK_1H_DAYS до 40. Для полного Top-300 передайте распакованный полный исходный архив вместо сокращённого `fixtures/market_2057`. В regression fixtures сохранены неизменённые строки выбранных активов; происхождение и хеши рядом. Исторические cutoffs не получают будущие свечи и live ticker, но snapshot liquidity ranks не являются историческими рангами: это не тест прибыльности без информации из будущего.

Успешный тест доказывает выполнение проверенного условия, а не уникальность Elliott-разметки. Рейтинг 0–10 остаётся эвристической оценкой, не вероятностью достижения цели и не копией субъективных оценок модели 5.6. Неподтверждённые расхождения других ручных сценариев перечислены в аудите; желаемые числа не прошиты по тикерам.
