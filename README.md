# Telegram Senior Wave Scanner v0024

Точечный релиз на базе v0023: маршруты XAU/XAG и видимость источника истории TON/GRAM. Формулы, волновая методология, рейтинг, scheduler, Search commit и SQLite не изменены. Детектор сохраняет внутреннюю версию 0023, чтобы обновление API не вызывало принудительный пересчёт всех сохранённых разметок.

## Изменения v0024

| Выбор биржи | Инструмент | Источник свечей |
|---|---|---|
| Binance Spot | Криптовалюты, включая GRAM | Binance Spot, прежний `/api/v3/klines` |
| Binance Spot | XAU, XAG | Binance USD-M Futures: `/fapi/v1/exchangeInfo` и `/fapi/v1/klines`, точные XAUUSDT/XAGUSDT |
| Binance Spot | USOIL | Явная недоступность, если отсутствует в актуальном каталоге контрактов; замены другой биржей нет |
| MEXC Futures | XAG | SILVER_USDT из каталога биржи, отображаемый как SILVER(XAG); XAG_USDT поддержан, если биржа перечисляет его явно |
| MEXC Futures | XAU, USOIL | Прежние XAU_USDT и USOIL_USDT |

Ввод `xag`, `XAGUSDT`, `XAG_USDT`, `XAG/USDT` нормализуется в XAG. На MEXC допустим также `SILVER_USDT`. XAUT не подменяет XAU. XAG использует существующую проверку календаря металлов, а дубли, неверные OHLC и close_time по-прежнему отклоняются. XAG доступен по ручному запросу; постоянные дополнительные инструменты Search остаются XAU и USOIL. Серебро не занимает криптовалютный слот Top-N.

**GRAM не получает готовую волну по имени.** Для Binance бот скачивает официальные месячные архивы TONUSDT 1D с `data.binance.vision`, проверяет SHA-256 и использует их вместе с новыми свечами GRAMUSDT как дневной контекст. Вшиты только документированные соответствия тикеров, даты перехода и коэффициент 1:1. Цены, экстремумы и цели в runtime не вшиты, parquet fixtures runtime не читает. Подпись `TON→GRAM` появляется после успешной загрузки; URL, SHA-256 и границы восстановленной истории сохранены в приложенном txt. При ошибке источника подписи успешного восстановления нет. Для MEXC остаётся цепочка TON-фьючерсы → MEXC Spot → Binance Spot, с отдельным спотовым контекстом.

В этой проверке через настоящий HTTP успешно получены 9 месячных архивов TON: 03.10.2025–29.06.2026, 270 закрытых дневных свечей; вместе с архивными GRAM получены 363 D1. Свечи текущего GRAM для этой проверки взяты из parquet на 03.10.2026, это не проверка текущего GRAM API. Детектор вычислил родителя 1.124→2.907→1.286 по данным, без назначения этой структуры по тикеру. Подробности: `AUDIT_v0024.md`, `CHANGELOG_v0024.md`, `audit/v0024/live-binance-ton-verification.json`.

## Поведение

- **Low:** `296.49 · 42.15%` — цена и максимальная глубина от исходного импульса. **Fib / статус** — положение закрытых COMPLETE4H относительно Fib исходного импульса и число удержаний. Это разные показатели.
- **W2/W3-(2):** прежняя формула `low + (1 / 1.618 / 2.618 / 4.236) × длина импульса`. Для W3-(2) используется W3-(1) от parent W2, без подмены коротким внутренним импульсом.
- **W4:** сценарная разметка после найденной структуры пяти движений. Глубина/Fib считаются по W3; отдельные цели W5 — `W4 low + (0.618 / 1 / 1.618) × внешняя W1`. Это три уровня; некоторые могут лежать ниже W3 high и соответствовать усечению. В txt сохранены все якоря, коэффициенты и пометки. Закрытие COMPLETE4H выше W3 high переводит Track в W5. Старые зоны W4 после этого убираются, low фиксируется; пробой low отменяет сценарий.
- **GRAM:** при недоступности TON-фьючерсов проверяется MEXC Spot, затем Binance Spot. Спотовая история служит только доказательством старшей степени; low, Fib и цели остаются на фьючерсах. Она не склеивается с фьючерсными OHLC. Старый одноимённый, но другой GRAM исключён по документированным датам. В таблице виден источник контекста; если он не найден, бот это сообщает.
- **STOCK:** подстрока исключается независимо от регистра до выбора Top-N, а также в Track старых наборов. Существующий набор БД не стирается: новый Search заменит его после успешной доставки и commit. Явный ручной запрос остаётся доступным, как для стейблкоинов.

Search отбирает W2/W3-(2); W4/W5 доступны в ручном анализе и сопровождении, но не добавляются в TOP-10 этой стратегии. /walk по-прежнему не изменяет рабочий tracked-set. Автоинтервал считается от успешной доставки полного отчёта. Отсутствующие XAU/USOIL не заменяются другими инструментами.

## Обновление / Coolify

1. Сохраните постоянный volume `/data`; разверните архив целиком.
2. Если Coolify переопределяет `BOT_VERSION`, установите **0024** либо удалите переопределение. Пересоберите Docker image, проверьте v0024 в таблице.
3. Используйте одну реплику long polling с одним Telegram token. SQLite и сохранённый tracked-set остаются в `/data`. Reset для обновления не нужен.
4. Для перехода с v0023 принудительный пересчёт разметки и Reset не нужны. Track использует прежний сохранённый набор. Новый Search нужен, чтобы отсутствовавшее ранее золото Binance попало в новый набор; commit по-прежнему выполняется только после успешной выдачи.

```bash
cp .env.example .env
# Заполните BOT_TOKEN; .env не включается в архив/публичный репозиторий.
docker compose up --build -d
```

Dockerfile устанавливает Pillow-зависимости/шрифт DejaVu. Runtime не требует parquet/pyarrow, а offline replay требует requirements-dev.txt. Не сокращайте стандартные 120 дней H1 до 40: точность старших якорей зависит от доступной истории. Новое обозначение времени `1D` применяется только при уточнении степени без изменения уже выбранного origin; недоступные более старые ценовые якоря не выдумываются.

Бот не размещает ордера. Рейтинг 0–10 — прежняя эвристика, не вероятность достижения цены. Сценарий W4 может оказаться расширением W3; сохранённые доказательства не означают единственность Elliott-разметки.
